# BirdStamp 局部主体稳定：产品接入实现方案

> 状态：开发方案，**不是已完成的 GUI 功能**。现有实验仅实现三组两帧的局部平移配准。
>
> 代码基线：`experiment/subject-stabilization-debug-20260930`，实验基线提交 `c360a8b`。先阅读 [实验报告](README.md)，再按本文实施。后续主线如有变化，必须重新确认接入点，不能直接覆盖同名模块。

## 1. 目标与范围

在天空、水面等缺少可靠静止背景的照片序列中，复用现有 YOLO 选择目标鸟，在用户确认的局部区域内估计运动，规划主体构图并通过整图平移或等效裁剪中心移动减少跳动。保持鸟的真实动作，不抠图搬动鸟，不生成中间帧，不重绘羽毛。

**第一阶段只承诺「指定局部后的主体稳定」，不承诺相机运动重建。** 单凭活动鸟的图像，不能唯一分离相机位移和鸟的真实运动；同一只鸟的头、躯干、翅膀、腿也不一定具有共同运动。

| 范围 | 第一阶段 | 后续独立评估 |
| --- | --- | --- |
| 目标鸟 | 复用 YOLO / 已有检测缓存，用户确认目标 | 多目标重识别、长时遮挡重识别 |
| 稳定参考 | 人工矩形/多边形 ROI，可设置关键帧 | 自动推荐局部，不默认替代用户确认 |
| 变换 | 仅平移，缩放恒为 1，旋转恒为 0 | 有独立置信度的尺寸稳定 |
| 稳定模式 | 局部锁定；保留轨迹趋势的自然跟随 | 自动镜头意图判断 |
| 失败处理 | 失败标记、暂停补偿、人工关键帧 | 更强点跟踪后端 |
| 不做 | 失焦细节恢复、非刚性形变、生成补边 | 不应混入本功能验收 |

## 3. 数据流与坐标契约

```text
源照片 / 源路径 / 显式序列顺序
  → 统一 EXIF 方向，划分连续片段
  → 复用检测结果并确认同一目标鸟
  → 用户指定参考局部与关键帧
  → 后台生成分析 ROI 和 source→analysis 坐标映射
  → 局部点跟踪与质量检查
  → 每帧观测 Observation
  → 整段稳定计划 Plan（中心、裁剪、状态、诊断）
  → 现有裁剪 / 渲染 / 信息栏 / 导出管线
```

### 3.1 必须保存的坐标信息

每帧保存源图尺寸、EXIF 方向处理方式、分析 ROI 在源图中的偏移与缩放，以及 source↔analysis 的可逆映射。跟踪结果先恢复至统一的源图坐标，再用于序列比较与导出。屏幕缩放和平移只影响 DEBUG 绘制。

对于只含分析裁剪与缩放的情况：`p_source = p_analysis / scale + roi_origin`。若还做了旋转、补边或其它预处理，必须使用组合矩阵，不能只乘宽高比。

不能逐帧按整鸟框裁成不同视野、统一缩放后，直接比较处理图中的距离。这样会把预处理造成的尺度变化当成鸟的变化。不能把预览 JPEG 的文件路径或尺寸替代原图语义。

### 3.2 建议的数据对象

| 对象 | 必要字段 |
| --- | --- |
| `SubjectSelection` | 目标身份、参考源帧、用户选择点/框、检测模型标识、检测来源签名 |
| `LocalAnchor` | 稳定的 anchor_id、参考帧、归一化多边形、fit/diagnostic/exclude 角色、人工/建议来源 |
| `FrameObservation` | 源文件签名、坐标映射、对应点 ID、坐标、可见性、前后向误差、各区域运动、失败原因 |
| `FramePlan` | 源图坐标下的裁剪中心或单一变换、状态、补偿强度、诊断指标、有效图像区域 |
| `SequencePlan` | 源帧顺序、片段边界、关键帧、配置版本、统一裁剪、计划签名、逐帧结果 |

空值不得隐式解释为 `(0,0)`。无纹理、遮挡和跟踪丢失要有显式状态，不能把失败帧显示为「已稳定」。

## 4. 目标选择：复用 YOLO，而不是重建检测器

首帧由用户点击目标鸟，利用已有检测结果确定候选。后续帧结合预测位置、框重叠和局部匹配保持目标连续性；多只鸟交叉、检测歧义时要求确认，不能每帧改选最大或最高置信度的鸟。

整鸟框只用于候选定位、搜索范围与完整构图保护，不直接提供稳定锚点或尺寸。没有检测结果时允许人工选择，不启动第二套模型作为隐式兜底。复用已有工作线程和缓存；前台 GUI 不执行模型加载或推理。

当前实验 `target_box` 仅用于限制参考帧的人工 ROI，**尚未实现逐帧身份关联或完整 YOLO 接入**。不要把这个可选参数描述成已经完成目标跟踪。

## 5. 局部跟踪与运动估计

### 5.1 建立参考

每个连续片段选一张清晰帧作为关键帧，用户指定一个或多个局部区域。头部锁定、站姿参考、躯干参考是不同视觉目标，不是具有保证的解剖检测模式。

双腿只是在本次三组站立样本中可用。飞行、迈步、浮水时不能默认锁腿；躯干白羽也可能缺少纹理。至少提供自定义 ROI 和补关键帧入口。

### 5.2 候选点与跟踪

第一版沿用 Shi–Tomasi + 金字塔 LK，加入显式前后向跟踪、有限值、图像边界、最大搜索位移等检查。特征按空间网格取样，避免全部来自某一小片高对比边缘。参与拟合的重叠区域要去重，不能让同一点重复投票。

**ROI 只限制点中心，不限制 LK 的全部采样邻域。** 细腿附近的窗口可能包含水面。候选区可内缩、限制窗口、增加局部纹理与邻域纯度诊断，但小局部内缩后可能根本没有足够角点；此时应失败/请求新参考，不应降低所有阈值强行通过。

未来可换更强点跟踪后端，但保持相同的 Observation / Plan 接口。模型可见性预测和遮挡外推不应当作直接图像观测。

### 5.3 先检查各区域，再估计共同平移

每个区域独立估计对应点的位移共识，再检查参与区域之间是否一致。两个区域显著冲突时，不取二者平均制造一个「折中运动」。一个头部区域和两条腿是否可以共同拟合，应由数据决定，而非按名称默认同属刚体。

生产版采用区域均衡或限制每区投票上限，避免某一区域角点过多压倒其它区域。当前实验先做区域冲突检查，再汇总有效点拟合；区域均衡是计划中的增强，不能算作已实现。

每个参考点应有持续 ID。可见点集合变化时，不直接把剩余点质心当成稳定锚点；使用参考局部的固定虚拟锚点及估计变换，避免遮挡引发人工跳动。

### 5.4 置信度不等于一个随意加权的概率

保留可解释指标：有效点数、前后向通过率、共识比例、残差分位数、空间覆盖、区域间冲突、边界风险及检测身份歧义。先用硬门槛决定是否可信，综合分数仅用于排序和 UI，不能宣称为校准过的成功概率。

实验默认值仅作为当前分析分辨率下的起点：

| 参数 | 实验起点 |
| --- | ---: |
| 每区最大角点数 | 140 |
| 前后向误差阈值 | 1.5 px |
| 平移共识距离阈值 | 2.5 px |
| 每区最少局部内点 | 5 |
| 总共识最少内点 | 12 |
| 最低有效跟踪比例 | 0.4 |
| 最低共识比例 | 0.5 |
| 参考区域位移最大分歧 | 3.5 px |

上述像素单位是分析图像素。正式应用应固定分析尺度或显式换算阈值，并在高像素 RAW、不同预览尺寸和小主体上重新标定。不能直接照搬到原生 5000 万像素图像。

## 6. 稳定计划与渲染

### 6.1 平移符号：warp 与裁剪中心相反

令 `d_t = p_t - p_ref`，表示参考帧到当前帧的主体局部位移。

- 对整图做 warp：当前帧补偿为 `-d_t`。
- 在原图中移动裁剪窗口：锁定局部时，裁剪中心应为 `c_ref + d_t`。

现有 `stable_center` 表示裁剪中心，不是 warp 偏移。实验 `report.correction` 为负向图像补偿，**不能直接加到 stable_center**。用合成平移和独立输出位置测试这一符号约定。

### 6.2 两种模式

**局部锁定：**固定参考锚点在输出中的位置。用户应清楚，头部锁定会保留腿部相对运动，站姿参考会保留头颈动作。

**自然跟随：**对可信的主体路径规划平滑目标轨迹，再用目标位置与观测位置的差形成补偿。平滑强度按片段调整；拍摄时间间隔优先使用有效时间戳，缺少时间戳时明确按帧顺序处理。不能把自然跟随称为已经分离了手抖。

原型尚未实现整段轨迹平滑。仅有两帧时不能可靠估计长时间趋势，继续按两帧实验解释。三次拍摄不得自动串成六帧连续轨迹。

### 6.3 裁剪与一次重采样

第一版尽量通过已有裁剪中心实现平移，不再在另一层重复 warp。需要亚像素变换时，由渲染阶段组合补偿、裁剪和最终缩放，一次采样源图，再绘制信息栏和边框。

整段共同有效区和完整动作范围共同约束裁剪。展翅范围可参与「保留画面」判断，但不能反过来驱动逐帧大小归一化。不能每帧裁成鸟刚好占满画面而重新引入尺寸跳动。

无法同时满足无黑边、完整翅膀和强锁定时，提示用户减弱稳定、扩大留边或分段。裁剪中心被边界约束后，必须记录实际应用的中心与残差风险，不能继续显示未实际执行的理想补偿。

## 7. 失败状态与关键帧

建议状态：`reference`、`tracked`、`low_confidence`、`needs_keyframe`、`user_override`、`skipped`。

| 情况 | 要求 |
| --- | --- |
| 少量点失败，其余局部有共同运动 | 降权/剔除失败点，保留诊断 |
| 左右参考区显著不一致 | needs_keyframe，提示可能迈步、姿态变化或错误匹配 |
| 严重失焦、无纹理、目标丢失 | 不输出假成功；暂停自动更新并要求参考 |
| 短暂缺测 | 第一版默认标记；后续可仅插值变换参数，必须标为 inferred，不插值照片内容 |
| 目标身份歧义 | 停止自动关联，要求用户确认 |
| 拍摄间隔大 / 视角突变 | 分段或新关键帧，不强行跨段跟踪 |

重新选参考后只重算受影响片段。不得在不告知用户的情况下从锁腿切换到锁头，否则视觉目标已经改变。

## 8. GUI、工作线程与缓存

在现有去抖动界面增加「局部主体稳定」策略、参考区域编辑、局部锁定/自然跟随、稳定强度、关键帧、失败帧定位以及 DEBUG 开关。保留现有 A/B 预览和播放条，不建立第二套独立预览管线。

DEBUG 分开显示：人工 ROI、真正的分割掩膜（如果未来加入）、局部投影 ROI、真实匹配点、拒绝点、目标轨迹、应用后的裁剪边界。绿色代表参与拟合，不代表世界静止；半透明区域的来源要可见。

分析线程接收不可变快照；窗口切图或参数修改用 token 拒绝迟到结果；取消后等待 worker 真正结束再释放。不要在 GUI 线程解码整批 RAW、跑跟踪或写报告。检测、解码、跟踪、计划和渲染缓存按既有生命周期管理并设置内存预算。

分两层缓存：

1. Observation 缓存：源文件签名、顺序、方向/分析尺寸、目标身份、关键帧、ROI、跟踪参数、算法版本。改变稳定强度不应重跑点跟踪。
2. Plan 缓存：Observation 签名、稳定模式/强度、时间轴、裁剪约束、人工修正。只改导出编码参数不应失效跟踪缓存。

缓存路径不使用可公开报告中的个人绝对路径；持久化设置应能识别旧版本并安全回退。

## 9. CLI 与调试数据

保留实验 CLI 的可复现性；生产 CLI 与 GUI 调用同一核心。图像输入目录只读，导出目录显式指定。报告至少保存：源文件名/签名、坐标系、参考配置、各区域运动、共识统计、失败原因、最终应用的补偿和裁剪。

NPZ 中保留真实对应点，JSON 记录数值，DEBUG 图只作展示，不反向成为数值来源。分享报告不包含字体文件、模型权重、私人绝对路径或未获授权的原片。

实验命令见 [README](README.md)。生产命令名在接入时确定，不在文档中冒充已可运行的子命令。

## 10. 测试与验收

### 10.1 已有基线

原实验记录：7 项合成单元测试、三组真实照片配准。已验证的主体补偿如下，单位为 2048×1365 输入像素：

| 组 | dx | dy | 内点 / 有效点 | 内点残差中位数 |
| --- | ---: | ---: | ---: | ---: |
| A | +3.418 | -15.357 | 34 / 43 | 1.224 |
| B | -5.973 | +2.653 | 40 / 42 | 0.601 |
| C | -6.327 | -16.826 | 53 / 62 | 1.471 |

这些是拟合一致性，不是相机运动真值精度。C 组锁腿后头部约剩余 (+1.064, -12.380) px 的相对运动，不应继续拉伸身体去消掉它。

### 10.2 接入必须新增的验证

| 测试 | 验收标准 |
| --- | --- |
| 已知合成平移 | 估计方向与裁剪中心方向正确，误差门槛在固定数据/分析尺度上预先设定 |
| 局部外强运动 | 不能因水纹或飞过的另一只鸟改变目标身份/稳定语义 |
| 扑翼但身体位置不变 | 不产生随翼展变化的缩放或旋转 |
| 头腿不同运动 / 迈步 | 不要求各部位同时重合；冲突能触发拒绝或人工处理 |
| 低纹理 / 失焦 / 遮挡 | 不崩溃、不写 NaN、不默认为零位移成功 |
| 分辨率 / EXIF / ROI映射 | 分析与导出的源坐标一致，不随视口缩放漂移 |
| 少数点全部挤在一起 | 空间覆盖不足时降级；不把密集点数当作足够证据 |
| 边界与裁剪 | 最终实际输出不越界，边界导致的稳定减弱可见 |
| 取消 / 切图 / 关闭 / 重新配置 | 无迟到结果覆盖、无线程提前销毁、无失控内存增长 |
| 旧工作区与旧策略 | 关闭新功能时行为不变；工作区可正常恢复 |

对真实数据，独立标注或未参与拟合的验证点用于评价；不能只报告拟合内点上的残差。测性能时报告硬件、源尺寸、分析尺寸、冷/热缓存、分阶段耗时、峰值内存，不以本次三组素材外推全部机型 FPS。

### 10.3 发布前检查

按仓库 [AGENTS.md](../../AGENTS.md) 和 [AI_CODING_RULES.md](../../ai_rules/AI_CODING_RULES.md) 执行编译、相关单测、GUI/工作区回归、取消关闭验证；必要时做 Windows/macOS 打包冒烟测试。本实验没有完成这些产品级检查。

| 阶段 | 交付物 | 进入下一阶段的门槛 |
| --- | --- | --- |
| P0：保留实验基线 | 现有 CLI、真实报告、图示、明确边界 | 开发者能用同一六张图复现；不声称 GUI 已接入 |
| P1：核心与裁剪接入 | subject_local 策略、坐标契约、类型化计划、失败状态、CLI | 关闭新策略无回归；合成位移和三个样本通过 |
| P2：交互与复用 YOLO | 目标确认、人工 ROI、关键帧、A/B 与 DEBUG、取消/缓存 | 不重复建模型，身份歧义与失败帧可处理 |
| P3：整段序列 | 自然跟随、片段边界、长期漂移控制、统一裁剪 | 连续片段验证；不强行桥接不连续拍摄 |
| P4：可选增强 | 自动候选局部、替换跟踪后端、尺寸稳定 | 各自独立数据集、许可审查、性能与回归验证 |

优先完成 P1/P2，不先引入 SAM、大模型或非刚性变换。自动化程度应在失败可见、手工修正可用之后提高。

## 12. 开发约束与完成定义

所有功能改动在隔离的功能分支/工作树中完成，遵循仓库工作流；本实验发布分支不自动合并到 main。不要修改现有 YOLO 的模型选择和全局参数，不修改 app_common 子模块，不改照片源文件，不把未授权原片或字体文件加入仓库。

第一版完成应同时具备：GUI/CLI 共用核心；明确目标与局部选择；正确源坐标与裁剪符号；失败状态/关键帧；可追溯 DEBUG；旧流程回归；目标平台验证。只有算法原型或三组成功示例，不算产品接入完成。
