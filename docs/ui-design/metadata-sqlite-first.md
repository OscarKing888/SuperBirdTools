# SQLite 提交和侧车同步状态

适用：SuperViewer 信息/EXIF/标签页、共享 FileListPanel、BirdStamp 元数据消费者。

选型：沿用 L1 主窗口和既有 `MetadataProgressDialog`；L4 列表/EXIF 表格保持原模型；L5 沿用状态栏、底部元数据进度标签、原生编辑器和按钮。不新增布局、折叠组、滚动容器或配色。

业务状态由 MetadataStore 保存：提交中、本机已保存/侧车待同步、同步完成、同步失败。SQLite 提交成功后更新受影响字段；不能将本机提交称为“已写入 XMP”。失败显示原有状态组件，并保留输入与待同步编辑。

`MetadataCommitBridge` 在 Qt 所有者线程交付 Future；界面关闭停止投递，后台提交/运行中操作仍受所有者管理。切目录保留缓存与已提交编辑；晚到结果校验路径/请求版本，标签或后台更新只刷新相关展示，不重置备注、文件名草稿、光标、撤销栈或预览视野。

复制、移动、改名和删除通过同一桥接到 worker，状态栏显示同步及操作结果。目录改名保留树节点、展开状态与选择，用户在操作期间切换目录时不强制跳回旧目录。原有非模态批量进度窗口继续拥有停止/关闭动作。

保持展开的标签菜单订阅提交后的缓存通知，同步更新重复叶节点和“清除”按钮。菜单过滤输入、展开状态和布局保留；通知连接由菜单子对象拥有，菜单销毁后不再访问控件。

验证：离屏小窗口、深浅主题、放大字体及现有菜单键盘回归；检查状态文本几何及截图。元数据同步和首屏性能以行为/线程/I/O 断言验证，不以样式字符串替代。

本轮完成 Viewer 1080×760 浅色 10pt / 深色 15pt 和 BirdStamp 两主题离屏渲染。发现并修正失败提示在窄进度区域的裁切：常驻文案只显示“XMP 同步失败 N · 自动重试”，详情放入 tooltip；放大字体下文字 246×26，小于控件 286×30。没有改变原布局、配色和焦点顺序。
