# SuperViewer 文件保护标识设计

状态：UI 设计稿。截图中的文件状态为演示数据，尚未接入文件系统检测。

## 组件与布局

宿主为 SuperViewer 主窗口的现有文件浏览区；L4 文件列表 / 缩略图列表中的
L5 状态反馈。复用原生列表委托、`BirdThumbnailDelegate`、Qt palette 和现有
ToolTipRole。无需新增列、工具栏或设置页；原列表继续负责滚动、伸缩和键盘选择。

```text
文件列表： # │ [锁 / 等宽空位] 文件名… │ 连拍 │ 鸟名 │ 评级 │ …

缩略图：   ┌─────────────────┐
           │              [锁]│ ← 卡片图像区右上角
           │      照片        │
           ├─────────────────┤
           │ 鸟名 / 等级徽章   │
           │ 筛片 / 对焦 / 星级 │
           └─────────────────┘
              连拍编号 文件名
```

文件名列固定预留 20 DIP 状态槽；图标 14–16 DIP、与文字间隔 4 DIP，普通文件只留
空位，名称对齐。文字过长按原规则省略，锁始终可见；图标不进入排序、复制文件名或
搜索文本。若文件名列已有图标，锁与原图标并排，不能覆盖原图标。
窄面板保留文件名列的可读宽度，由现有横向滚动容纳其余列。

缩略图在**图像区容器**右上角内缩 6 DIP，使用 22 × 22 DIP 圆角深色半透明底板、
14 DIP 白色锁，保证亮图和暗图中均清楚。位置跟随卡片而非实际图片边缘，横图、竖图、
加载占位保持一致。最小 128 档不缩小图标；较大档位也不随照片同比放大。大字体 / DPI
缩放时用逻辑像素和矢量绘制。底栏、视频角标、连拍分组和选中边框仍保留各自位置。

## 状态与交互

| 原图文件状态 | 图标 | 悬停附加提示 |
| --- | --- | --- |
| 普通可写 | 无 | 无附加保护提示 |
| 只读 | 闭合锁 | 原始文件：只读 |
| 系统锁定 | 同一闭合锁 | 原始文件：已锁定 |
| 同时只读、锁定 | 一把闭合锁 | 原始文件：只读、已锁定 |
| 尚未取得状态 | 暂不画锁 | 如需展示状态，应写“文件保护状态：待检测”，不能宣称可写 |
| 状态检测失败 | 不猜测、不画锁 | 文件保护状态：无法读取 |

列表锁使用正常文本色，选中时使用高亮文本色；照片角标保持白锁深底。
不以红、黄颜色区分原因，避免与筛片 / 评级 / 色标混淆。整行和照片维持正常对比度。

悬停文件名或缩略图时，在原有完整文件名、路径和元数据提示中追加保护状态。
键盘选中项的可访问说明也包含该状态。锁是被动标识，无独立焦点、不改变光标，点击和
双击仍执行原来的选择 / 打开，不提供点击解锁操作。系统属性变化后在刷新目录、回到
应用或重新扫描时更新对应项，保留当前选择、排序、滚动位置和已解码缩略图。

“锁定”在本稿中指系统可查询的持久文件保护状态，例如 macOS Finder 锁定。
Windows 只读属性也显示锁。其他程序的瞬时占用锁属于操作失败原因，不能仅凭一次
读取失败就当作持久锁定。实现时需按平台验证，不尝试写原文件来探测状态。

锁标识说明的是**原图**。元数据写入同名 XMP，不能根据原图只读状态就禁用鸟名、
标签、评级编辑；XMP 或目录是否可写由实际写入路径独立判断。

## 实现落点与验收

- 状态模型：以实际源路径为键保存只读 / 锁定 / 未知及原因；后台扫描，绘制只查缓存。
  不用预览 JPEG、report.db 路径或 XMP 状态替代源图状态，不在 paint、悬停或长按切图中做 I/O。
- 视图：Viewer 列表模型 / 文件名委托与 `thumbnail_metadata.py` 的 Viewer 扩展共同读取
  同一状态。需要共享能力时先登记 `docs/ui-style.md`；本轮仅含设计脚本，无运行组件变更。
- 普通、只读、锁定、两者同时、未知 / 失败；两视图一致，同图切换视图状态不丢失。
- 最小 128 档、256 档、窄文件名列、长中文名、放大字体、深浅色、选中 / 悬停、横竖图、
  亮暗照片、加载占位和视频；状态不遮挡已有角标或底栏。
- 刷新、筛选、排序和状态变化保留选择 / 滚动；列表模式不生成缩略图，长按不新增文件读取。
- 实现后的 Windows 64 位与 macOS 分别验证真实属性，不能将 macOS Fusion 渲染当作 Windows 验证。
