# SuperViewer 目录操作与文件拖放

## 文件夹重命名

```text
目录右键 → 重命名文件夹… → 原生 QInputDialog（预填原名）
                        → 名称/已有目标/编辑保护检查 → 改名并更新受影响路径
```

L5 动作绑定右击目录；取消或名称未变不操作，非法名称、重名或权限失败提示后可重试。
复用目录名校验，不覆盖已有文件/目录；磁盘或挂载根、忙碌和关闭时禁用，执行前重新检查。
已知照片编辑会话、加载、保存及批处理输入按目录范围检查，保护待保存的 XMP。
核心 `native_file_transfer.rename_directory()` 不依赖 Qt，目录整体改名携带照片、XMP 和内部缓存，
大小写改名失败尝试恢复，恢复失败报告保留路径。`ViewerDirectoryBrowser.directory_renamed()`
只更新已加载节点的路径及目标名称，保留当前节点、展开和滚动；当前浏览目录在目标内时沿新路径
加载，在目标父目录内时只刷新文件列表，无关目录保持不变。清理受影响的旧预览和标签历史，
沿用只读报告的路径解析，不写 report.db。此入口为目录导航操作，不新增 CLI 或持久化选项。
Windows 改名前通过共享 `meta_disk_cache.directory_file_operation()` 释放目录内 SQLite 缓存句柄，
在原子文件系统操作期间阻止重新打开；迟到的缓存写入不能复建旧照片目录。
成功后向既有实际路径缓存登记旧/新照片路径，报告候选路径查询沿会话别名匹配，支持连续改名，
保留报告原始 `current_path` 与 XMP 路径。报告位于被改名目录内或其上级时均验证数据库字节不变。
覆盖见 `SuperViewer/tests/test_directory_rename.py`：中文目录/照片/XMP、非法名称/已有目标、
大小写与失败恢复、当前目录/祖先/父目录/无关目录的列表和缩略图、展开与选择、菜单键盘、
取消、编辑保护及忙碌/关闭。

## 交互与组件

```text
目录树 L4                         文件列表 / 缩略图 L4
├─ 目录右键 → 新建子目录… L5       └─ 多选 → 拖动原文件 + 同名 XMP
│  └─ QInputDialog 输入名称             ↓ 默认移动 / 实体 Ctrl 复制
├─ 粘贴到此文件夹 → 剪贴板文件 + XMP    光标：→ 移动 / ＋ 复制
└─ 目标目录：主题高亮描边 ←─────────────┘
   └─ 悬停展开、边缘滚动 → 系统操作窗口 → 状态栏结果
```

沿用共享目录浏览器的懒加载、目录菜单与滚动归属，新增原生名称输入框；输入取消不创建目录。
创建成功仅向已有父节点插入新节点并展开，当前浏览目录、文件多选和已有展开子树保留。
名称校验遵守 Windows/macOS 的共同文件名限制，不允许路径或递归创建。

`app_common` 提供 `directory_tree_class`、`file_table_view_class`、`thumbnail_view_class`
工厂，默认仍为原有 Qt 视图。Viewer 的派生模型仅增加可拖动标志，原有稀有度列、徽章、排序
和缩略图缓存仍由原模型实现。两个拖动视图复用原生选择处理，按下已选行不丢失多选；
不修改方向键播放事件。目录树只接收本窗口当前拖动令牌，空白、占位、外来或过期拖动被拒绝。
目录选择记忆和待剪切显示仍保留；延迟滚动定位由面板持有的定时器执行，关闭时拒绝访问模型，
面板销毁时取消回调，避免文件操作刷新后迅速关窗访问已释放的模型。
高亮仅绘制边框，不改变当前目录或文件预览。实体 Ctrl 在 macOS 映射为 Qt MetaModifier，
Windows 映射为 ControlModifier；放下时读取当前状态，因此拖动途中可以切换复制/移动。

L5 光标由 `file_drag_feedback.file_drag_cursor()` 按视图字体、palette 与 DPR 绘制箭头、
操作符号和文字，通过原生 `QDrag.setDragCursor()` 分别注册复制与移动，由 Qt 根据目标接受的
动作切换；不使用全局 override cursor，不读取图片，不增加计时器或持久化状态。
禁止目标保留系统光标；进入目录树时立即校验落点，空白与占位行不短暂显示可放下提示。
接口依据：[Qt QDrag](https://doc.qt.io/qt-6/qdrag.html#setDragCursor)。

L5 原生目录菜单增加“粘贴到此文件夹”，绑定右击路径而非当前浏览目录；空剪贴板、
非文件文本、目标已失效、文件保护不允许、已有系统操作或关闭期间禁用/拒绝。
菜单打开后再执行也重新读取剪贴板并验证状态。内部剪切为移动、内部/外部复制为复制，
复用后台系统操作及严格同名 XMP 解析；支持外部仅提供照片 URL 时发现配套 XMP。
当前浏览目录、目录树选择与展开保持，只有受影响的当前文件列表刷新。
剪切粘贴加入同一移动历史，取消或部分完成保留剪贴板；照片与 XMP 全部移动成功后，
仅当剪贴板代次未变化才清除，避免覆盖操作期间新复制的内容。无新增布局或滚动区。

## 数据与系统操作

控制器复用浏览器的实际源路径与 XMP 收集接口，拒绝把缓存预览当作源文件，
后台提交前再次通过严格同名侧车解析器获取当前 XMP，RAW/JPEG 共用侧车只提交一次。
同目录移动跳过；同目录复制也由系统决定。图片和 XMP 是同一系统批次的独立文件，
具体覆盖、跳过、保留两份和取消均遵循系统窗口中用户对各文件的选择；不自动覆盖、不回滚系统结果。

Windows 使用 [SHFileOperationW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shfileoperationw)，
STA worker、Unicode 双 NUL 路径数组、`FOF_ALLOWUNDO`，检查返回值和 `fAnyOperationsAborted`；
不设置静默、自动覆盖或自动改名标志。系统窗口不归属隐藏中的 Qt 主窗口，关闭等待时仍可取消。
macOS 使用 CoreServices Apple Event：`core/move` 或 `core/clon`，文件 URL 描述符，
目标参数 `insh`，等待完成并允许 Finder 交互；所有描述符在成功/失败时释放。
参数选型参照 [Apple Developer Forums 的 Finder 原生冲突窗口验证](https://developer.apple.com/forums/thread/804786)。
打包加入 Finder 自动化用途说明和 Apple Events entitlement；权限拒绝明确显示系统设置入口，
不回退到没有系统冲突对话框的文件复制实现。

后台线程独立于当前目录，运行期间不能启动第二批。实际 `QThread.finished` 后，
按已消失的源文件清理预览、标签撤销记录和只读报告缓存的会话标记；`report.db` 不写入。
当前目录涵盖源或目标时按实际磁盘刷新，系统取消也处理部分完成，不删除尚存在的源文件。
主窗关闭等待系统窗口结束及真实线程完成，不强杀系统文件操作。

这是依赖交互式系统冲突窗口的拖放与目录粘贴能力，无新增 CLI；核心系统适配与目录校验不依赖 Qt。
原有文件列表的“粘贴到当前目录”与归档事务保持原策略，新增目录入口使用系统冲突窗口。

## 移动撤销 / 重做

L5 动作复用原生 `QAction` 与现有历史箭头图标，编辑菜单和目录右键菜单共享同一对
“撤销移动 / 重做移动”。不新增面板或滚动区，标签工具栏及文本编辑器的原生撤销保持原入口。

```text
编辑菜单                         目录右键菜单
├─ 撤销标签 / 重做标签             ├─ 新建子目录…
└─ 撤销移动 / 重做移动 ←共享动作→  └─ 撤销移动 / 重做移动
```

控制器拥有最多 100 批的会话历史；每批保存实际完成文件的来源、去向和文件身份。
跨卷移动按摘要确认完成；撤销/重做返回已记录路径时，仅依照已验证的来源关系更新更早历史的
文件身份，避免跨卷重新创建文件 ID 后连续撤销失效。哈希准备可随关闭请求取消。
后台执行撤销/重做，沿用系统移动；执行期间禁用两个动作和新拖放，目录仍可切换。
部分完成只将成功的部分转入反向历史，取消或失败的未完成部分可重试；空操作不清空重做。
照片与 XMP 同批处理，当前照片的新增/更新 XMP 随照片返回，不恢复旧元数据字节。
撤销前验证文件仍是同一文件且原位置空闲，缺失、替换、目标被占用时保留历史并提示，
不静默覆盖其它文件。原始系统操作中覆盖已有文件或改变文件名的结果不进入可撤销历史，
完成后明确报告数量；系统未提供可恢复的覆盖前副本，不能假称可以完整还原。
复制不加入移动历史。历史不落盘，也不调用 Finder/Explorer 的全局撤销以免影响应用外操作。
恢复后只移除对应实际路径的报告会话删除标记并重新读取报告；`report.db` 不写入。
