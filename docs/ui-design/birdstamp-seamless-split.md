# BirdStamp 连屏切图

处理设置中与图片处理、去抖动、拼图并列。单张源照片的横向等分；每张比例决定总裁剪比例（份数 × 单张宽高比）。普通裁剪和连屏裁剪各自保存。

```text
照片列表              │ 整体裁剪 / 逐张预览
图片处理 去抖动 拼图 连屏切图
  ▾ 切分设置          │ 调整裁剪框 / 分割线 / 编号 / 适应 / 100% / 缩放
    份数、每张比例    │
    分辨率、宽高      │ EditorPreviewCanvas 独立派生画布
  ▾ 构图设置          │ 整体：源图 + 总裁剪框 + 等距线
    裁满/完整补边     │ 逐张：成片切片 + 上一张/下一张
    背景、重置、撤销  │
  ▾ 输出设置          │
──────────────────────│
状态/进度（固定）
[导出当前张（2/3）]（固定满行）
[导出整组] [取消]（固定）
```

- L1 沿用 CurrentPageTabWidget 与右侧 QStackedWidget；独立控制器持有参数、逐图裁剪和后台 worker，切页不销毁。
- L2 左侧主 QScrollArea 统一滚动，窄窗口允许横向滚动；ExportActionBar 固定动作。工具栏按两行排列，原生布局可伸缩。
- L3 三组 CollapsibleSection 默认展开；折叠不修改参数、不触发解码。
- L4 PreviewWithStatusBar + SplitPreviewCanvas 复用 EditorPreviewCanvas 的比例裁剪与坐标；分割线和编号仅绘制到视口。ImageOutputOptionsForm 复用五种目录语义；PNG 标签明确本功能为 8 位输出。
- L5 原生组合框、数值框、ColorEditor、ToggleToolButton；整体/逐张互斥，独立布尔工具。深浅主题来自 palette，不新增 QSS。

默认 3 张、每张 3:4、1080×1440、裁满、PNG、每次选择目录；切换 JPEG 时质量默认 95。已有工作区显式保存的格式/目录模式继续恢复，空状态和新建工作区使用新默认。份数 2–20，单边 64–8192，总画布不超过 100 MP，非法组合显示原因且禁用导出。完整显示模式保留全图并补边，不提供裁剪拖动；切回裁满恢复原构图。比例/份数改变尽量保留中心和面积；拖动在源图内约束，不延伸到不可见区域。单次手势只记一条撤销，逐图历史仅在会话内保存。

每张图保存独立裁剪框，全局份数/比例/尺寸/输出与显示开关随工作区保存；路径使用现有相对路径序列化。切页结束拖动、停止播放；连屏不接管其他页面的 A/B 和普通裁剪。预览焦点内左右键仅切换切片。输入为源照片，不隐式套用模板或去抖动结果。

核心由无 Qt 的 SplitOptions / SplitCanvasStage / SplitExportStage 实现，GUI 与 CLI 共用。预览后台有界解码，导出只使用完整源图；总画布统一采样后按整数边界切片。独立管线不注册到普通图片/GIF/视频的阶段列表；无帧缓存。按用户指定的连屏导出策略，只调用现有 copy_export_metadata 保存原生 EXIF/ICC、校正方向和尺寸；不读取 XMP 快照、不写侧车、不内嵌 XMP。此例外仅限连屏，普通导出保持图片/XMP 配对。单张和整组共用完整总画布，page_index 只选择写出的切片，确保像素与整组对应张一致。整个临时目录有即时所有权；完成后发布到新的、不重名的结果目录，不覆盖既有整组。

后台单 worker + 最新待处理请求，版本与 worker 身份过滤迟到结果，真实 finished 后才交接。导出时参数/构图冻结，切页可继续，取消可达；工作区切换取消旧任务并丢弃旧结果。关闭协作取消并等待实际线程退出。

验证：拼回 PNG 与总画布逐像素一致；奇数像素、各种比例、补边、透明/旋转、无效尺寸；中文 EXIF 读回、输出没有 XMP、原图及原侧车不变；取消/失败与重名发布；工作区往返、切图、真实拖动、键盘、迟到结果和关闭；小窗口/放大字体/深浅色实际离屏截图。CLI 同核心入口。

## 使用

在照片列表选择图片，切换「连屏切图」，设置份数和每张宽高。整体裁剪中拖动框和手柄调整构图；逐张预览中使用上一张/下一张或画布焦点内的左右键检查。裁满和完整补边共用同一总画布规则，完整补边时不启用裁剪拖动。分割线与编号不会导出。导出到所选目录下的 `原名_连屏`，重名自动编号；默认组内为 `原名_01.png` 等，不生成 XMP。逐张预览选择后点击「导出当前张（编号/总数）」，仅输出该编号图片至新的 `原名_连屏_编号` 目录，重名同样自动编号。整体视图中单张按钮禁用并提示切换逐张预览；导出期间两种导出按钮、切片导航和参数禁用，取消保持可达。取消目录选择不启动任务或创建目录。

从 `SuperBirdStamp` 目录使用仓库虚拟环境的解释器，可运行 `python -m birdstamp split photo.jpg --output out --count 3 --width 1080 --height 1440 --format png`。`--crop left,top,right,bottom` 接收源图归一化总裁剪框，`--fit contain` 保留完整照片并补边，`--background` 设置背景。GUI/CLI 都拒绝超过上限的总画布，不静默降低导出尺寸。CLI 默认 PNG；`--page 2` 仅导出第 2 张，编号超出切分份数时不创建输出。

## 早期 3:5 参考预设（历史记录，已由下节校准方案替代）

以下记录解释旧工作区的 `3:5` 来源，不是当前的无缝推荐；普通图片笔记全屏滑动实测不匹配，当前标签已恢复为普通“3:5”。

资料与证据边界：

- [Photix 裁图工具](https://crop.photix.cc/) 的作者页面将“小红书竖屏全屏”列为 3:5，同时将竖向视频列为 9:16。页面本身注明预览仅供参考，需保存后尝试。它支持选择设备，不是小红书官方规范。
- [文小图：小红书 3:5 图片全屏发布](https://wenxiaotu.cn/help/publishing/xiaohongshu-fullscreen)（页面标注更新 2026-09-18）同样采用 3:5，展示经“写文字 → 写长文”进入并替换模板图片的发布流程。这是工具作者的操作资料，说明图片比例之外还涉及发布入口，不能推导为所有客户端的统一规则。
- [等分裁图作者的 App Store 页面](https://apps.apple.com/cn/app/id6739728712) 声明支持小红书全屏无缝裁剪，但公开说明没有给出对应数值或补偿算法，因此不据此猜测裁切补偿。
- 本轮未找到小红书官方对“全屏连屏”承诺统一比例的文档；未在用户账号发布笔记，未验证其手机上的实际接缝。用户截图包含上下操作栏，不能把整屏约 9:19.5 当作图片容器比例。此前 1080×2340 仅是条件性试验建议，不作为产品预设。

## 小红书全屏：按实际显示区校准（2026-11-09）

### 证据与比对方法

本次针对普通“图片笔记 → 全屏图”入口。用户确认接缝出现在横向拖动期间，停在单张时无内部接缝。[3:5 使用反馈](https://github.com/yeban8090/note-to-red/issues/32) 与上节文小图教程讨论长文图文，不能证明这个入口的无缝比例。目前没有找到平台对所有机型/客户端承诺统一比例的资料。

用户文件只读比对，照片和下载图均不加入仓库测试资产：

| 样本 | 几何与结果 |
| --- | --- |
| `frame_00000573_01/02/03.png` | 每张 1080×1800，RGB；三个文件均无 ICC；边界相邻列平均绝对差约 1.411 / 1.102（8 位 RGB），相邻内部列差约 1.27–1.61，未发现明显切片断层 |
| 发布后下载的 `2fb59e9e727324eece338437ae0bf2c3.jpg` / `da7268190574f6318a1e2173e125489e.jpg` | 每张 810×1350，对应前两张 PNG。SIFT + RANSAC 相似变换尺度约 0.749959 / 0.750010，84 / 714 个内点，匹配中位误差 0.255 / 0.329 px；没有明显再次裁切证据 |
| 下载图与原 PNG 75% 缩小 | 灰度平均绝对差约 1.733 / 2.314（0–255），相关系数约 0.998595 / 0.997400；压缩和缩放误差存在，不能要求下载 JPEG 逐像素相等 |
| 发布截图 `codex-clipboard-4b163abb-cb27-41e2-b3bd-243a4531c569.jpg` | 原始 1280×2774；可见图片区约 y=342..2506，即 1280×2164，排除上下操作栏 |
| 前两张 PNG → 截图 | SIFT + RANSAC 相似变换尺度约 1.202126 / 1.202077；横向平移约 −731.073 / 548.654，纵向约 342.023 / 342.427；91 / 317 内点，中位误差 0.426 / 0.415 px |

方法：用 OpenCV SIFT（最多 8000 特征、最近邻比值 0.7）匹配；截图匹配限制在 y=350..2450，`estimateAffinePartial2D` RANSAC 误差阈值 2 px；下载图用 1 px。由匹配尺度推算显示图片宽约 1298 px，但页面间距约 1280 px，差约 18.5 屏幕像素，即约 15.4 个原图像素。共用尺度拟合得到间距约 1280.29、图片宽约 1298.96，推算损失约 15.52 原图像素，与上述判断一致。这是截图几何推断，不是小红书内部实现证明。

结论：本组导出边界和下载图几何基本连续，主要不匹配发生在全屏滑动显示阶段。按观察到的图片区做等比铺满模型，3:5 显示宽为 1298.4 px，需要隐藏 18.4 px；新校准尺寸把这部分横向裁失消除。画面边界测量仍有像素误差，实际客户端是否始终采用这个模型需重新发布验证。

### 当前界面与状态

L3 继续使用“切分设置”共享 CollapsibleSection；L4 使用原生 QFormLayout 和无标题 QWidget 容纳两行校准输入；L5 使用 QComboBox、QLineEdit、可换行 QLabel，无新增 QSS。参数和说明随主滚动区滚动，固定导出区保持可达；长选项按表单换行。折叠、切页、切换普通比例均保留校准值。

```text
▾ 切分设置
  切分份数          [3]
  每张比例          [小红书全屏（校准） ▾]
  显示区宽度（px）  [1280]   ← 仅校准模式显示
  显示区高度（px）  [2164]
  校准参考 · 每张 1080 × 1826 px
  输入图片显示区域，不含上下操作栏；截图参考，需发布验证。
  每张分辨率        [短边 1080 px ▾]
  每张宽度 [1080] / 每张高度 [1826]
  总画布 3240 × 1826 px · 共 3 张
```

- 普通 `3:5` 仅修改标签；旧工作区尺寸、裁剪中心和构图不迁移。新工作区默认普通 `3:4`。
- 校准标识为 `xhs_fullscreen_calibrated`，同级 `fullscreen_calibration` 保存 `width` / `height`。缺失校准字段默认 1280 / 2164，不会使旧工作区进入校准模式。
- 输入允许暂时为空或非法文本以便编辑；必须是正整数且高大于宽才可预览/导出。合法数值按整数保存，非法草稿按文本保留。超限计算结果保留在目标尺寸模型中，明确显示所需尺寸和错误；数值框保留可编辑值，不以框的上限替换输出。
- 核心 `resolve_split_ratio` 统一处理固定、自定义、校准比例；`split_dimensions` 使用整数运算。按宽度计算 `ceil(width × display_height / display_width)`；按高度计算 `floor(height × display_width / display_height)`，不再因取整扩大图片横向显示宽度。

| 短边宽度 | 每张校准输出 | 1280×2164 等比铺满模拟 |
| --- | --- | --- |
| 1080 | 1080×1826 | 横向裁失 0；纵向裁失约 0.148 px |
| 1440 | 1440×2435 | 横向裁失 0；纵向裁失约 0.444 px |
| 2160 | 2160×3652 | 横向裁失 0；纵向裁失约 0.148 px |

这里纵向数值为上下合计裁掉的不到一个屏幕像素。最终宽高仍须满足单边 64–8192、总画布不超过 100 MP，否则显示原因并禁用两种导出。仍在完整总画布统一采样后等分，不加入重叠像素、重复边界或未经验证的补偿。份数、构图、PNG、每次选择目录、单张/整组导出保持原规则。

CLI 不新增标识或参数，直接使用 `split --width 1080 --height 1826 --count 3 --format png`；`SplitOptions` 不增加平台字段。没有截图导入、自动识别、多机型预设管理。本次不重新打包 EXE。

验收边界：数学和像素测试验证当前校准值，界面继续使用“校准参考”。用户需通过同一“图片笔记 → 全屏图”入口重新发布，按编号排序，不逐张二次裁剪，再检查横向拖动接缝。该尺寸不是平台通用标准，也未验证其他机型、客户端或 macOS 实机界面。
