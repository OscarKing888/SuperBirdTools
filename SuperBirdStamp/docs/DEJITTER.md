# 参考区去抖动

## 使用流程

1. 在“导出 → 导出设置”调整裁切比例、裁切框和留边，需要统一构图时使用“全部应用”。
2. 切到同组的“去抖动”标签页。右侧仍使用原预览画布，自动进入去抖动编辑模式；“编辑构图 / 成片预览”切换条只在此页显示。返回导出设置会恢复原来的编辑模式。
3. 选择参考照片，点击“框选 / 追加选区”。拖框圈出鸟头等形态稳定的纹理或静止背景；Shift 拖框追加多个参考区。选区持续显示，参考编辑模式提供四边、四角共 8 个手柄，松手后保存。切图不会更换已确定的参考照片。
4. 框选自动启用“参考区对齐”，默认强度 100%；0% 不补偿。未启用参考区时，可使用“自动构图平滑”，它需要在导出设置开启统一自动裁切尺寸。界面明确显示当前生效方式；“不裁切”或关闭模板裁切时禁用分析，但保留选区与参数。
5. 点击“分析并预览成片”，后台分析整组照片，并通过真实导出图像管线生成当前图。按钮可取消。成片视图显示去抖、裁切、尺寸限制、模板叠加等处理后的画面；切图按需生成其它成片，已生成的画面使用有上限的缓存。
6. 切回“编辑构图”可查看各编号参考区在每张照片上的跟踪位置；目标图上的框只读，失配区域不绘制。“编辑参考图”返回原参考照片继续调整。
7. 满意后返回“导出设置”导出图片、GIF 或视频。有效的整组裁切计划会复用到导出，即使仅导出部分照片，也不会重新按子集计算构图。

参考线、焦点框、鸟体识别框、缩放等沿用同一画布与工具栏开关；成片中的辅助框按照实际裁切和补边变换，参考线限制在成片区域内。辅助显示不会写入导出照片，管线中明确开启的“焦点框”叠加则属于真实成片。成片预览是**图像处理完成后的源帧**；视频画布适配、GIF 调色板与播放时序、最终编码不在本次预览中。

关闭参考区开关会保留选区；右键或“清除参考区”明确删除。参考照片、区域和强度随工作区保存；重新打开工作区需要重新分析。普通编辑模式持续显示参考图上的轮廓，只有参考区编辑模式显示手柄。

**跟踪框表示各区域在原图中的位置；成片视图才显示实际裁切补偿。** 多区均匹配成功不等于各区位移一致，核心仍会做多数共识检查；分析摘要中的“参考区失配”只描述跟踪质量，不宣称所有帧都已稳定。

修改设置、参考区、照片列表或恢复工作区使旧成片失效。源图、参考图、XMP 和模板文件签名变化也禁止复用旧结果，界面提示重新分析。后台逐张解码并关闭图像，不缓存整组原图；取消与关闭会拒绝迟到结果，直到线程真实结束才释放所有权。用户分析期间主动返回编辑视图，结果到达不会抢回成片视图。

## 裁剪和坐标语义

- 参考区保存在经过方向纠正的源图归一化坐标中；预览缩放和四侧补边仅在交互显示时转换。完全位于补边中的框选不是有效纹理区。
- 手动裁剪保留每张照片的框尺寸和原有构图偏移，在其中心上叠加参考区位移；需要锁定相同构图，应先应用相同裁剪设置到整组。
- 自动裁剪以参考照片的裁剪中心为锚点，按目标源尺寸换算后加上位移。原比例、自由比例均支持。“不裁切”始终不改变原图。
- 自动统一尺寸沿用原分组规则，不覆盖手动裁剪尺寸。补偿使裁剪框越界时使用现有留边颜色，避免通过逐帧缩放或夹紧中心重新引入抖动。需要无补边输出时，应主动留出足够的裁剪余量。
- 参考照片可以不在本次导出子集中。GUI 快照携带参考照片的裁剪设置；不可读取的参考文件会报错，请重新框选，不会静默换成第一张照片。
- 匹配失败的帧保留原裁剪中心，日志报告数量；不会在没有可靠纹理时强行对齐。由于这是退回原构图，失败帧仍可能有可见跳动，应换一个更稳定/更大的参考区。

## 算法选择与边界

[当前实现](../birdstamp/image_dejitter/numpy_phase_correlation_aligner.py) 使用 NumPy 相位相关进行粗定位，再在峰附近做 20 倍采样密度的局部 DFT 细化。局部矩阵 DFT 的思路参考 [Guizar-Sicairos 等人的亚像素配准论文](https://doi.org/10.1364/OL.33.000156)；相比全图上采样，它只细化相关峰附近的小窗口。相位相关的平移模型也见 [OpenCV 官方说明](https://docs.opencv.org/4.13.0/d7/df3/group__imgproc__motion.html)。本实现不新增 OpenCV、GPU 或其他运行时依赖。

可靠性检查包含有限数值、纹理方差、峰旁瓣比、竞争峰、真实重叠区域的亮度归一化相关，以及多个参考区的位移多数共识。两个区域明显冲突时拒绝虚构平均位移。每帧直接匹配固定参考，避免逐帧累加漂移；逐帧释放匹配 patch，长序列不累计灰度图数组。

这是一种针对连拍**平移抖动**的工程选择，不宣称所有场景最优。当前 patch 为 192×192；位移接近任一参考区轴长的 40% 会被拒绝，避免周期绕回。形变、转头、翅膀摆动、大幅旋转/缩放、遮挡和极弱纹理不在稳定平移模型的能力范围。参考区应包含足够的稳定纹理，多个区域应具有相同运动；不要把运动的鸟和静止背景混为一组。

亚像素精度用于估计位移；最终裁剪仍按原图整像素边界取样，保持既有图像管线和清晰度，不额外插值扭曲图像。源图尺寸不同采用归一化映射，不能修正不同拍摄视角或不同的预先裁剪。

## 接口、缓存和验证

- 跟踪核心：[ReferenceRegionTracker](../birdstamp/image_dejitter/reference_region_tracker.py) 接收参考图与多个源图归一化区域，`track(image)` 返回按区域原顺序保存的匹配框（`None` 表示失配）；接口独立于 Qt，适合批处理复用。独立页由 [EditorSequencePreviewWorker](../birdstamp/gui/editor_sequence_preview_worker.py) 统一调度整组裁切与逐区跟踪；原跟踪控制位于 [editor_reference_tracking.py](../birdstamp/gui/editor_reference_tracking.py)。
- 核心入口：[prepare_uniform_auto_crop_plans](../birdstamp/export_stage/core.py)，输入 `VideoFrameJob` 列表，输出各作业的 `crop_plan`。处理在模板裁切前进行，不另建图片/GIF/视频各自的去抖算法。
- 设置：`dejitter_strategy="reference_region"`、`dejitter_reference_enabled`、`dejitter_reference_regions`、`dejitter_reference_source`、`dejitter_reference_strength`。导出子集可附 `dejitter_reference_crop_settings`；省略时沿用首个作业的构图设置。
- [sequence_preview.py](../birdstamp/export_stage/sequence_preview.py) 保存输入签名、整组作业与裁切计划；`render_video_frame_context` 与导出同入口，并返回辅助层所需几何。`crop_plan_prepared` 仅由验证有效的结果设置，禁止子集导出或视频磁盘缓存重新覆盖已确认计划。
- 成片缓存长边默认 1600、总预算默认 64 MiB，通过 `config/editor_options.json` 的 `dejitter_preview_max_edge`、`dejitter_preview_cache_mb` 配置；只缩小最终位图，不用小图重新匹配或排文字。
- GUI 默认强度由 `config/editor_options.json` 读取。阶段参数在 `ImageProcTemplateCropStage.parameter_options()` 中描述。旧工作区没有独立强度时默认 100%，中位中心防抖语义保持不变。
- 全局设置、强度、参考文件签名及预计算裁剪结果参与源帧缓存失效；源帧缓存版本提升为 6。引用文件同路径替换也会使帧签名改变。
- 现有单图 `birdstamp render` CLI 不包含序列参考区交互，此轮不扩展它的参数契约；批处理代码可直接使用上述共享核心接口。
- 回归：[test_dejitter.py](../tests/test_dejitter.py)、[test_video_export_dejitter.py](../tests/test_video_export_dejitter.py)、[test_editor_dejitter.py](../tests/test_editor_dejitter.py)，覆盖已知整数/小数位移、亮度变化、失配、多区冲突、手动裁剪像素对齐、子集导出、取消、缓存和工作区状态。跟踪及线程所有权回归见 [test_reference_tracking.py](../tests/test_reference_tracking.py)，包含多选区、部分失配、文件变化、取消和关闭窗口的迟到结果。真实相机序列仍应按素材检验参考区选择；合成数据通过不代表任何素材均能匹配。

标签页、辅助层坐标、像素一致性、整组计划复用、输入失效、缓存上限及线程取消回归见 [test_dejitter_tab.py](../tests/test_dejitter_tab.py)。
