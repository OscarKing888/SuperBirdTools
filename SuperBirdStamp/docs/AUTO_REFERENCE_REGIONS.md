# 按算法推荐参考区

去抖动的「1. 选区」提供 **一键推荐选区**。基本方法寻找背景；高级方法可使用本地鸟类部位模型。两者共用后台抽样预检，并保留人工选区。推荐不是全序列成功保证，仍需执行「分析并预览成片」。

## 操作与边界

- **基本方法**：YOLO 排除鸟体，结合原有角点候选与多尺度宽轮廓选区。拒绝近乎单方向的纹理，再用实际参考匹配器检查唯一性和组合运动一致性。不为凑目标数量加入不可靠区域。
- **高级方法**：默认手动选区。勾选「使用实验性部位识别」并安装模型后，可推荐头部、躯干或可见腿部。多鸟时弹出带裁片的候选按钮，确认目标后再点击推荐。也可手动指定部位；没有可信候选时明确拒绝，不自动改成背景稳定。
- 部位识别目前是**实验功能，默认关闭**。真实样本存在高置信度错误关节，背身、遮挡、展翅不能视为已经验证。识别到部位不等于该部位物理静止，也不保证它有足够纹理用于跟踪。
- 默认抽样参考帧、其后两帧、25%/50%/75% 位置及末帧，去重后最多七张。短序列全部检查。候选必须通过所有抽样帧；匹配位置还须与同名部位相符。优先最差帧质量，接近时优先躯干、头部、腿部。
- 重新推荐替换上次自动区，保留人工区；拖动或缩放自动区后，该区成为人工区。高级方法不自动混入已有人工区，基本方法检查人工区与新候选是否共同成立。
- 目标鸟和部位在完整分析时固定。检测只定位局部搜索窗口，不使用框中心或框大小变化作为补偿。不支持跨长时遮挡重识别；身份歧义须手动处理。
- 部位识别后立即显示「部位候选」草稿和裁片，预检结束后保留每个部位的通过数量、失败帧和原因。虚线表示待检/需修正，实线表示抽样通过。草稿不进入导出设置；点击「采用此候选并手动修正」后才进入现有画布编辑，完整分析通过后才能导出。已有人工区冲突时保留原区，不混入其他运动部位。未采用的草稿仅在当前会话保留，切图/设置变化/取消时失效；采用后的目标和部位随工作区保存。
- 主体预检的关键点与跟踪仍最多抽样七张，但身份关联会补齐中间照片，按时间逐张比较预测位置、外观及候选竞争。参考图在中间时分别向前/后关联。高分辨率局部重检只用于漏检、单框或明确包含关系的重复框，重检必须唯一且较可信；独立的多鸟竞争不能被局部漏检消除。身份中断后不跨越失败帧重选鸟，需人工关键帧重新确认。

## 模型与坐标

使用官方 Animal Kingdom 鸟类 HRNet-W32、256×256 输入、23 个关键点。推理保留 RGB 标准化、1.25 倍正方形、翻转测试和 MSRA 四分之一像素热图修正；与官方权重键严格对应。部位候选还检查翻转一致性和鸟框范围。

权重大小 **114746485 字节（约 109 MiB）**，固定 SHA-256：

`566feff57cbf6ebcc84d111741c85ce49e07e940b450b646638f1e45587cfb15`

下载/离线导入写到用户数据目录 `models/`，先写临时文件、校验、再原子替换。可以取消，不自动安装依赖、不在启动时下载、不上传照片。使用现有 Torch，优先 CUDA/MPS，不支持时回退 CPU。YOLO 仍使用应用现有实例和设备策略；加入跨调用锁，预览检测与推荐不会并发操作同一实例。

打开界面时在后台校验已安装模型：通过后按钮显示「下载完成 ✅」并禁用重复下载。缺失时允许下载，损坏时显示「重新下载」；下载和离线导入后自动刷新。文件被删除或替换时重新校验，平时仅检查文件属性，不反复读取 109 MiB 权重。关闭窗口等待校验线程真实结束。

鸟类网络推理代码改编自 [Microsoft HRNet](https://github.com/leoxiaobin/deep-high-resolution-net.pytorch/blob/master/lib/models/pose_hrnet.py)，保留 MIT 声明和完整许可（亦嵌入 Python 模块，随打包分发）。[MMPose 配置及官方鸟类权重](https://github.com/open-mmlab/mmpose/blob/main/configs/animal_2d_keypoint/topdown_heatmap/ak/hrnet_animalkingdom.md)、[23 点定义](https://github.com/open-mmlab/mmpose/blob/main/configs/_base_/datasets/ak.py)。本轮未引入 SAM 或 TAPIR。

手工选区与自动主体区使用同一测量：每个选区按自身尺寸取规范分析尺度（见 [局部主体稳定](SUBJECT_STABILIZATION.md#纹理孔径约束与链式关键帧2026-10-01)），窗口直接从源图带预滤波采样。有目标鸟时，轨迹框中心只给出搜索窗口的先验平移，不直接改变补偿。分别记录参考/当前窗口原点与分析比例，所有点和最终位移恢复至 EXIF 定向后的源像素。完整人工修正建立新关键帧，沿用原分析比例与纹理角色。

## 模块与持久化

- `image_dejitter/region_recommendation.py`：GUI/CLI 共用推荐结果、确定性抽样、质量和同名部位/多区一致性核验。
- `image_dejitter/bird_candidates.py`、`bird_parts/`：全部鸟候选、有界 3×3 漏检补充、固定权重校验、独立鸟类关键点后端。
- `image_dejitter/local_crop_tracker.py`：局部分析到源坐标的映射、缓存、人工关键帧。先调用原有 OpenCV LK，保留相同可靠性门槛；失败时调用独立的 `local_registration.py`。
- `image_dejitter/bird_observation_cache.py`：检测和关键点的 256 项 / 32 MiB 有界缓存，只保留数值；键包含源文件与模型属性、目标框。
- `gui/region_recommendation_panel.py`：后台推荐/安装、目标选择、取消与线程所有权。完成回调校验路径、文件签名、选区、算法和参数快照；关闭等真实线程结束。
- `target_trajectory.py` 与 `region_candidate_preview.py`：只读逐帧身份轨迹及候选草稿视图。检测和外观观测复用有界缓存，轨迹在并行分析前建立；身份失败和图像跟踪失败分别保留，不相互冒充成功。
- 全局设置 `dejitter_region_recommendation` 保存版本、目标框、请求部位、实际推荐部位、自动区来源、局部分析模式和模型版本。旧工作区缺失此字段时所有框为人工框。分析签名版本更新，旧派生结果重新计算，不改变原文件。

## CLI

```sh
# 显式下载，或追加 --source /path/to/official.pth 离线导入
PYTHONPATH=.:SuperBirdStamp .venv/bin/python3 -m birdstamp bird-parts-model

# 基本方法；输出不覆盖已有 JSON
PYTHONPATH=.:SuperBirdStamp .venv/bin/python3 -m birdstamp recommend-regions \
  frame1.JPG frame2.JPG --reference frame1.JPG --output roi.json

# 高级实验；多鸟时 --target 是报告中从 1 开始的鸟候选编号
PYTHONPATH=.:SuperBirdStamp .venv/bin/python3 -m birdstamp recommend-regions \
  frame1.JPG frame2.JPG --reference frame1.JPG --output subject-roi.json \
  --method subject_local --experimental-parts --part auto --target 1

PYTHONPATH=.:SuperBirdStamp .venv/bin/python3 -m birdstamp stabilize \
  frame1.JPG frame2.JPG --reference frame1.JPG --regions subject-roi.json \
  --method subject_local --output results
```

`--model-file` 可指定已验证的官方权重用于诊断。推荐失败或需选鸟也写 JSON，并退出码 2；报告包含原因和抽样文件名。Windows 设置对应的 `PYTHONPATH`，并使用仓库 `.venv\Scripts\python.exe`。

1. **已实施：分开显示候选和预检结论。** 检出鸟、识别部位后立即显示可确认的候选草稿；失败的候选保留虚线和具体帧/原因，不自动写成可导出的有效选区，也不替换现有人工区。成功显示通过数量，失败区分身份关联、部位不可见、纹理对应和部位运动冲突。验收：这组图能看到头/躯干候选，同时如实保留跟踪失败状态。
2. **已实施：按时间关联同一只鸟。** 先构建目标鸟轨迹：位置预测加外观核验，多鸟竞争时保留歧义；补中间帧检测，不用一直与首帧的固定半径比较。轨迹表完成后供并行跟踪任务只读使用，检测框仅决定局部窗口。验收：末帧不再因距首帧较远而误报丢失；加入两鸟交叉/遮挡测试，歧义时仍拒绝跳鸟，框抖动不产生补偿。
3. **已实施保守版：同部位多候选与第二种图像配准。** 在可信关键点支持范围内生成多个尺度和纹理子区，避免电线、翼尖和其他独立运动部位；先试 1.0/1.3/1.6 尺度，但不能把扩框视为已解决。加入局部相关匹配初始化，再验证平移 ECC 或 LK；ECC 作为独立后端，需要相关峰唯一性、正反向一致性、有效覆盖和同部位证据，不能用降低 LK 内点门槛替代验证。[OpenCV 官方接口](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html)提供初始光流及平移 ECC。验收：对人工标注部位做源像素误差对照，并把重复电线、错误背景、头躯干相对运动作为必须拒绝的负样本；不能只报告更多帧通过。
4. **已实施有界版：姿态变化时分段关键帧核验。** 固定关键帧失败而相邻帧的同部位配准可靠时，提出新的关键帧；只有通过图像对应核验的连接才累计到原锚点，双向回查限制漂移。无法可靠连接时跳转失败帧，允许用户修正一次并继续，保持目标鸟及部位不变。验收：41 张逐帧检查实际姿态变化，报告自动通过率、需人工修正帧数、人工标注位置误差及误接受数量；无法锁定的部位仍明确拒绝，不要求用错误匹配换取 41/41。

## 3＋4 的实现与限制（2026-10-01 补充）

> 后续更新：下文“最多四张、两端须直接匹配原参考”的有界桥接已由逐帧链式关键帧取代（双向一致才融合，单侧受误差与 12 段上限约束），LK 失败后的 NCC/ECC 改为只对失配选区调用。详见 [局部主体稳定](SUBJECT_STABILIZATION.md#纹理孔径约束与链式关键帧2026-10-01)。

- `part_region_variants.py` 保留完整部位，并在可信支持框内生成 85%/70% 子区，按二维纹理筛出最多三个。没有采用向外扩框：鸟体附近的电线、翅膀与其他部位可能独立运动。左右腿可分别检验，关键点身份保持不变；双腿组合必须共同通过。每个候选有独立编号、通过数量、失败原因和 GUI 名称，不会把同名候选的计数相加。
- `local_registration.py` 在原 LK 失败后执行 NCC 唯一峰初始化、平移 ECC 精修、有效重叠质量、独立反向搜索以及四分块一致性检查。NCC 至少 0.86，远离主峰的竞争峰差至少 0.06；精修后有效区域的相关度至少 0.88，正反向误差最多 0.75 分析像素，至少三个分块支持共同位移。重复电线、单方向边缘、遮挡和部位运动冲突均拒绝。ECC 迭代返回值不直接充当最终质量，在排除边界采样后的有效重叠内重新计算相关度。诊断标明 `ncc_ecc` 和真实子块对应，不冒充 LK 内点。
- `subject_keyframes.py` 对最多四张的连续失配短段进行双向分段核验。两端必须各自直接匹配原参考，每条链逐帧从真实图像重新配准，两侧累计位移须在 1.5 分析像素内一致；整段核验通过后才发布。保持初始分析比例，结果仍映射到原虚拟锚点。身份中断、长失配段、末尾缺锚点或任一方向失败，均保留拒绝与人工关键帧入口，不用已补出的结果无限继续串接。
- 合格的局部人工调整会扩大参考裁片以留足边界；远离目标鸟的框明确提示编号，不能与鸟体混用。用户当前配置包含头部框和两端背景框，此前误报“参考区必须在图像内”；现在明确提示“选区 2、3 远离目标鸟”，需删除背景框或切换基本方法后只保留背景。程序不会静默删框或更换目标。
- GUI 与 CLI 都通过同一生产管线使用以上行为，旧工作区自动区元数据仍兼容。自动分段结果记录两端关键帧路径，DEBUG 和整数导出使用同一源坐标；人工分段的 DEBUG 参考端也恢复到原锚点。分析签名升级到 10，局部观测键升级到 v3，避免复用旧结果。
