# 序列防抖 UX 设计

状态：设计方案与可交互样稿，尚未修改应用行为。基于 `90641e2` 的当前实现。

样稿：[stabilization-workflow.html](stabilization-workflow.html)。画面、位移与失配均为模拟数据，用于评审交互；不是算法测试或真实导出。以 HTML fragment 保存，可用 visualize 的 renderer 包装后在浏览器检查。

## 设计结论

把防抖从“导出 → 模板裁切”的长表单中独立出来，放在**构图之后、尺寸与模板叠加之前**。它是整组照片的处理步骤，用户需要先设参考、再分析、再查看成片。界面上独立成区，处理上仍由现有批量裁切计划与模板裁切阶段执行，不新增可任意上下移动的“防抖 Stage”。

主预览提供两个用途明确的视图：**编辑构图**保留原图、裁切框与参考区；**成片预览**显示执行防抖、裁切、缩放与叠加之后的输出画面。两个视图保持同一张照片，不因切换视图丢失选区、播放位置或设置。不要让用户把“跟踪框在移动”误解成“图像已经稳定”。

## 当前界面的问题与对应改动

| 当前问题 | 设计调整 |
| --- | --- |
| “批量预计算”一行包含统一尺寸和一个“防抖”滑块，下面又有“参考区去抖” | 统一尺寸留在构图；防抖方式集中为“关闭 / 构图平滑 / 参考区对齐”，采用互斥选择，只显示对应强度。 |
| 防抖埋在导出设置里，使用时却必须返回预览工具栏找选区工具 | 独立“序列防抖 · 整组 N 张”区域，直接提供“编辑参考图”“追加选区”“分析并预览”。工具栏仍可保留快捷入口。 |
| 选“不裁切”时仍可看到“参考区已启用 100%”，但实际不补偿 | 保留用户参数，显示“当前不裁切，防抖未生效”，禁用补偿/分析，提供显式“选择裁切比例并调整构图”。不偷偷改比例或清空选区。 |
| 主预览显示原裁切，导出时才出现补偿 | 增加真实的成片视图，分析完成自动进入；显示当前帧是已补偿、未补偿还是待更新。 |
| 大段说明承担了流程导航 | 用三个可见动作表达顺序：确定参考 → 分析整组 → 检查成片。说明缩成靠近控件的一句话。 |
| 处理管线、上移/下移、Stage 等实现词占据主要操作区 | 面向用户展示“构图 → 序列防抖 → 尺寸与叠加 → 输出”。现有可重排阶段放进“处理顺序”折叠区；裁切与防抖的依赖固定。 |

旧设置迁移必须以当前真正生效的策略为准：当前核心通过 `dejitter_strategy` 选择策略；参考区对齐与中位中心混合不是两个可自由叠加的防抖。不能仅根据两个滑块的数值猜测迁移模式。统一自动裁切尺寸仍可与参考区对齐同时使用。

## 排布与交互

### 设置区

1. **构图（逐张）**：模板、裁切比例、中心、留边、统一自动裁切尺寸。把“全部应用”改成“将当前构图应用到整组”，避免误以为会重新设置参考图。
2. **序列防抖（整组）**：方式选择；参考图文件名与区域数量；参考区编辑入口；分析主按钮、进度、取消；补偿强度；生效/失效状态。
3. **尺寸与模板叠加**：保留现有处理选项与顺序能力。
4. **输出**：图片 / GIF / 视频、范围、帧尺寸等；显示所用成片版本及未补偿帧数量。

参考区对齐模式分三步，但不做阻塞式向导。用户可随时返回前一步。已分析时主按钮变“重新分析并预览”；进行中原位变“取消分析”，保留真实进度。不要另设一个容易混淆的“预处理跟踪”和一个“生成稳定结果”主按钮。

构图平滑不要求框选参考区，隐藏参考编辑步骤，主动作改为“计算并预览”。强度 0% 显示“未补偿”，不能显示“已稳定”。未选区时把“在当前图框选参考区”作为主要操作，框选后才允许分析。

### 编辑构图视图

- 原参考图持续显示所有编号选区；进入参考编辑模式时，每个选区显示四边、四角 8 个手柄。
- Shift 拖框追加区域；“追加选区”直接进入同一工具。用户选择哪张作为参考就固定哪张，不随当前列表首图变化而重设。可以从当前图开始，并不强制必须列表第一张。
- 切换照片后，显示对应的跟踪框与原编号，只读。匹配失败的框不伪装成原地匹配；状态显示失败数。
- “编辑参考图”返回参考照片并激活编辑工具。参考照片不在列表时提示添加回列表，或由明确“更换参考图”操作重新建立参考，不隐式覆盖旧选区。
- 原图坐标与输出裁切坐标明确分离。编辑时保留固定基础构图框；可选的稳定后裁切轮廓只能作为另一个有标签的只读辅助层，不能覆盖可编辑基础框。

### 成片预览视图

- 只显示输出区域；默认没有裁切框、参考框、鸟框等编辑辅助线。模板文字、模板背景与用户启用的导出焦点框属于实际输出，应显示。
- 按住“对比未防抖”暂时显示相同设置下未补偿的成片，松开恢复。两者都保留相同裁切比例、尺寸与叠加；不能拿完整原图和稳定后成片作不等价比较。
- 提供逐张切换及“播放序列”，保持同一画布尺寸与观察尺度，避免每张自动适应缩放制造假性稳定。GIF / 视频按当前输出帧尺寸与时间计划播放；图片模式提供明确的预览帧率。
- 生成后自动切到成片视图，但用户主动退回编辑后，后台结果抵达不能再次抢回视图。
- 匹配失败帧明确标“未补偿”，可从摘要跳到第一张失败帧。逐区成功不等于多区位移一致，状态必须来自最终稳定策略，不能只用 `matched_count` 计算“已对齐”。

## 所见所得的技术契约

仅重新布局现有控件不足以实现本方案。当前 `ReferenceRegionTracker` 只提供区域位置，主预览没有消费最终裁切计划。以下是需要实施的接口边界：

1. **一次输入快照**：GUI 只快照照片顺序、源文件/参考文件及 XMP 签名、逐图设置、全局设置、模板内容、输出尺寸。后台补齐元数据，不能为预览在 GUI 线程同步解码整组原图或读取完整元数据。
2. **一次分析结果**：跟踪结果包括逐区位移、质量/拒绝原因；稳定策略消费它并产出逐帧补偿、失配回退原因与 `crop_plan`。预览、图片、GIF、视频共用该结果对象及有效性签名，不能各自从跟踪框推算另一套位移。
3. **同一渲染入口**：成片通过 `VideoFrameJob → render_video_frame → 默认 ImageProcPipeline` 生成。显示时可缩小最终位图，但不可先用不同尺寸素材重新估计位移、排文字或计算留边。预览像素缓存不得作为原尺寸导出源。
4. **同一输出边界**：GIF/视频还需应用对应帧尺寸归一化、背景与方向设置，预览才可称为该格式的成片。JPEG/GIF/视频的有损编码、调色板或播放器色彩差异不属于几何一致性的保证；要求编码后逐像素一致时应显示实际编码文件。
5. **同一序列范围**：分析基于界面明确的整组照片顺序；导出子集应复用整组已确认的逐帧计划，不能重新对导出子集取中位数导致构图变化。要重新分析子集，必须显式改变分析范围。
6. **同一版本**：设置改变后旧结果不能继续标“成片已更新”。有效的分析结果可以直接用于导出；失效时按钮指向“更新预览”，完成后供用户检查再导出。无需为每次正常导出额外增加确认弹窗。

建议将结果分为“跟踪”“稳定裁切”“成片像素”三层，避免每次调强度都重新读整组照片。通过有界缓存与后台 worker 实现，线程保留到真实 `finished`，新版本 token 拒绝旧结果。

| 变化 | 跟踪层 | 稳定裁切层 | 成片像素层 |
| --- | --- | --- | --- |
| 切换当前照片、切换视图 | 复用 | 复用 | 读取对应帧 |
| 调补偿强度 | 复用 | 重算 | 更新，短防抖延迟 |
| 修改裁切比例/中心/留边/统一尺寸 | 尽量复用源图跟踪 | 重算整组所需计划 | 更新 |
| 修改文字、模板外观或输出尺寸 | 复用 | 依赖未变时复用 | 按影响范围更新 |
| 修改参考图/参考区、源图内容 | 相关匹配失效 | 失效 | 失效 |
| 重排/增删照片 | 可复用仍有效的逐图匹配 | 重算序列范围相关计划 | 按新顺序更新 |
| XMP 元数据变化 | 像素跟踪可复用 | 焦点等依赖变化时失效 | 文字等依赖变化时失效 |

裁切参数变化不应强迫用户重新框选或重新匹配。界面用“更新成片”区分“重新分析参考区”，主动作仍只有一个，具体工作由失效层决定。样稿为突出状态转换，把结构性更改统一简化成“待分析”；这是演示限制，不是最终缓存策略。

## 边界状态

| 状态 | 用户看到什么 | 下一步 |
| --- | --- | --- |
| 未选择参考区 | 未设置参考；框选按钮 | 在当前图框选 |
| 已框选、未分析 | 参考图区域正常显示；其他图无伪跟踪框 | 分析并预览 |
| 不裁切 / 裁切不可用 | 未生效，保留参考与强度 | 选择比例后再分析 |
| 正在分析 | 真实阶段与进度；可取消 | 完成进入成片 |
| 全部通过 | 当前版本已更新 | 逐帧/播放/对比/导出 |
| 部分失配或多区分歧 | 待检查帧数及每帧实际回退行为 | 跳转失败帧，调整参考或接受原构图 |
| 设置已变化 | 成片正在更新或待更新；不把旧帧当新结果 | 更新后检查 |
| 取消 / 失败 | 回到可重试状态；不能保留“完成”标签 | 重新执行 |
| 文件同路径替换 / 工作区重开 | 校验签名；缓存不可验证时标待分析 | 重新计算 |

第一版保留现有“越界使用留边颜色”行为，并在成片显示真实补边。不要默默放大照片填满画框。未来可加入“自动缩小安全裁切区域”，但这是新的裁切策略，需要单独确认尺寸、画质与构图语义。

## 实施与验收顺序

1. 提取包含拒绝原因的分析结果及签名；让现有跟踪预览和导出消费同一份数据。保持八手柄、多选区、持久显示与现有裁切回归。
2. 在后台生成成片，接入主预览双视图；比较预览原始位图与同一作业 PNG 输出的像素、裁切、补边、文字和焦点框。
3. 调整侧栏布局、方式选择与默认状态；旧工作区恢复保持原有效策略。
4. 加序列播放、未防抖对比、失败帧导航与分层失效；覆盖取消后迟到结果、切图、修改选区、关闭窗口。
5. 验证图片子集、GIF 和视频实际输出的尺寸归一化与时间计划；检查 Windows 64 位和 macOS 的控件宽度、键盘操作与后台生命周期。

最低交互验收：多区八手柄可编辑；目标图跟踪只读；无裁切状态真实；0% 明确未补偿；失配框不伪造；整组/子集裁切一致；设置修改不显示过期成片；关闭与取消无悬空 QThread；编辑视图构图网格仍限定在裁切框内，辅助线不意外进入成片。

## 样稿验证

Safari 实际检查了成片/编辑切换、两个选区的八手柄展示、选区交互后的成片失效与导出禁用、分析阶段到完成、跳转第 7 张失配照片，以及“不裁切”时的未生效提示。检查了宽布局与 320px 宽布局。JavaScript 语法、元素引用、UTF-8 与文档相对链接也已检查。

样稿最多演示 4 个选区、8 张固定示意帧，播放使用演示节奏，裁切仅提供 16:9 / 不裁切；这些都不是应用最终限制。没有真实解码、特征匹配、输出编码或文件写出；本轮不声称应用已经实现成片所见所得。
